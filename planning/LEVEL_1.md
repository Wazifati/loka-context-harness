# Loka Framework Selection and Planning

Use this as the Agent-readable form of the original Loka Index. It preserves
version-specific use rather than merging the family into one workflow.

1. **Vague intent or non-technical context work:** use Loka ACE.
2. **Prompt/app planning or audit without repo/shell execution:** use LokaV10.
3. **Repository/CLI/IDE implementation:** use LokaV11.
4. **Supervised 1–3 hour V11 session:** add original LokaV12 Supervised.
5. **Bounded autonomous V11 mission:** add LokaV12 Autonomous Edition, the
   separate second edition.
6. **Vibe coding, visual prompt builders, or agentic visual IDEs:** use LokaV13.
   Switch to V11 after export to a real repository/IDE.

Loka Failures is a supporting planning and review catalogue. It informs any
relevant route but is not an execution version. Loka Guard is not packaged until
its original source is supplied.

## Loading rule

Choose the first matching route and stop. Do not stack V10, V11, and V13.
Only V12 editions load on top of V11, and the supervised and autonomous editions
should be selected by mission type rather than loaded together.
