# Loka ACE: Adaptive Context Engine

Use this as the planning entry point when the outcome, audience, constraints,
or success criteria are still unclear. It is a context engine, not a mandatory
form and not a request to delay simple work.

Build only the context layers that materially improve the result:

- **Aim**: outcome, audience, decision, and priority.
- **Character**: useful expertise and stance; never rely on persona alone.
- **Execution**: the reasoning or work sequence.
- **Constraints**: boundaries, resources, factuality, and safety requirements.
- **Export**: deliverable shape.
- **Evaluation**: observable criteria for a useful result.

If the request is clear and low-risk, infer the missing layers and proceed. If a
missing detail would materially alter a high-impact decision, ask the minimum
question or state a safe assumption. Separate known facts from assumptions.

Before technical execution, produce a compact handoff: goal, in/out of scope,
constraints, evidence required, and the suggested downstream skill. Use
`loka-build` for repo-capable implementation, `loka-session` for a bounded
autonomous mission, and `loka-guard` where risk boundaries are material.
